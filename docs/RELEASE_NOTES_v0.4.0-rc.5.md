# Muse Link v0.4.0-rc.5

本次修复全面审计发现的 5 项问题，仍是生产候选版。

- 空白 HTTP 200 不再误判发送成功；保留 unknown 和未确认事件，不自动重发。有效 JSON `{}` 继续兼容。
- 无效或空游标不覆盖已保存游标，批次保持原子提交。
- 持久化租约活动监测，长期无续租/checkpoint 会报告 worker_lease_stalled，不改变 token 或抢占任务。
- 媒体上传不再占用同一聊天的实际发送通道；`muse reply --async` 返回持久化请求编号，让单个 worker 继续回复短消息，全部 accepted 后才自动 ack。
- Linux 孤儿工具记录可经 reviewed reconcile 收尾，仍活跃的监督器/工具组会拒绝；保留稳定 ID，防止重复执行。启动屏障确保先持久化子进程身份再执行可信脚本。

升级必须同步更新真实 Muse worker/hook，采用异步媒体提交、逐轮回执查询和失败恢复流程。pending/202 不表示手机收到；不同任务可交错到达，每个请求内部保持顺序。后台异步发送随 daemon 运行，进程中断后需按持久化回执核对，不承诺自动恢复发送。

详见 [升级指令](给Muse升级的指令.txt)、[连续消息流程](BURST_MESSAGES.md) 和 [验证记录](VALIDATION_v0.4.0-rc.5.md)。真实 Muse hooks、手机文字/图片/视频及实际 72 小时运行验收仍待云端执行，不能据本地测试判定部署已经生产就绪。
