# v0.4.0-rc.2 复审记录

日期：2026-10-21。基线为已发布 rc.1 提交 `350831524b4db715e94766989cbe71bd7bb6d793`。范围为任务交接与发送、恢复去重、备份路径、配置与 HTTP 输入、依赖和本地部署。属于开发者复审及故障注入，不是独立渗透测试。

## 已修复

优先级表示本项目修复顺序，不是 CVSS 评分。P1 为可能影响任务重复/长时间停滞的可靠性问题，P2 为本地安全边界，P3 为输入或运维准确性问题。

| 优先级 | 触发及影响 | 修复与回归 |
| --- | --- | --- |
| P1 | 领取请求已取消，循环仍先领取再检查取消；任务可能被无接收者的请求占用，默认等 30 分钟租约恢复。 | 每次 Store.claim 前检查取消；覆盖已取消、新事件唤醒竞争和真实 HTTP 断开。 |
| P1 | Muse 回复排队或上传媒体期间换了租约，旧 worker 仍会发微信并完成任务。 | 排队出列及每次 chat 提交前检查当前租约；过期返回 stale_lease，保留已确认分段与上传引用，供当前 worker 恢复。覆盖排队和上传中换 worker。 |
| P1 | v0.3 的回执无 send_events 关联，90 天清理可能删掉尚未 ack 任务的 accepted/进度记录，丢失恢复去重依据。 | 任意任务未完成时保守保留无关联 muse-* 历史；测试先维护、再恢复 accepted、ack 后再清理，确认任务不重执行。 |
| P2 | 备份/恢复只比较字符串路径，父目录 symlink/junction 可将备份放入状态目录，或绕过 HOME、备份源与恢复目标的边界。 | 按现存祖先的真实路径比较，不存在的后缀也解析；拒绝覆盖 HOME/其祖先及源目标重叠。Windows/Linux 测试使用隔离假 HOME 和哨兵文件，未操作真实 HOME。 |
| P2 | 直接复制 config.example.json 后，公开示例 token 长度足够，会被当作有效认证配置。 | 限制 token 为 32..256 个无空格的可见 ASCII 字符；公开示例无法通过，init 随机生成值及原有 Base64 token 可用。不能靠格式检查证明 token 熵或私密性。 |
| P3 | operations 使用 in 检查，toString 等继承名称可被当作配置选项；checkpoint 将数字 step 隐式转字符串。 | 使用 Object.hasOwn，仅接受字符串 step；加入配置和 checkpoint 回归。未发现由此导致远程代码执行的证据。 |
| P3 | application/jsonp 被作为 JSON；请求 ID 的畸形百分号/UTF-8 编码产生 500。 | 精确检查 JSON 媒体类型，保留 charset 支持；统一 ID 解码/格式校验并返回 400，覆盖查询与 review。 |
| P3 | 升级指令称 muse next 默认只取一个，实际为 20；重新扫码未明确说明必须先停服务。 | 指令明确 --limit 1、实际默认值、暂停 hook 和停止服务后登录，避免积压租约与 state_locked。 |

任务领取、排队租约、历史保留、配置及 MIME 回归在修复前观察到失败，修复后通过；路径和上传续传由隔离回归及代码检查覆盖。新加 13 项测试位于 test/audit.test.mjs。[完整验证结果](VALIDATION_v0.4.0-rc.2.md) 记录了两平台测试和模拟收发。

## 尚未完成及信任边界

- **实际部署验收未执行**：没有真实 Muse 云端终端或微信账号连接。原生 hook、手机文字/图片收取、视频播放和实际 72 小时观测，继续按 [生产验收指令](给Muse生产验收的指令.txt) 完成。
- 已领取任务若在响应传递中断开，仍靠租约到期恢复；已经在网络中或提交给外部工具的动作无法由租约撤销。checkpoint 不保证所有外部副作用恰好执行一次，必须使用目标系统幂等键并核对遗留 started/unknown。
- API token、同一操作系统账号和 Muse worker 是信任边界。media_roots 不能抵抗同账号恶意进程并发替换文件；它不是操作系统沙箱。需要更强隔离时使用独立账号/容器；入站内容不得自行提升工具权限。
- 保持单账号、单实例、本地持久化磁盘。入站图片/视频/文件下载、多副本高可用和跨操作系统状态迁移尚未实现。出站图片/视频大小是本地上限，腾讯账号兼容性仍需实测。
- 历史幂等记录有保留期；旧记录清理后不保证永久去重。失败恢复暂存目录、旧 release、备份和系统日志需运维管理，磁盘预算不能代替文件系统配额。
- npm audit 当次结果为 0 个已知依赖漏洞；本次未发现的漏洞及未来供应链风险不能由这个结果排除。

升级使用新版本包，暂停 hook、停止服务、备份、更新 worker 后再启动；不覆盖 rc.1 已发布文件。部署边界和生产门槛见 [PRODUCTION.md](PRODUCTION.md)。
