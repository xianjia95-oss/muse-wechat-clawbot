# 外部 API 失败不能挡住微信消息

外部API 是用户交给 Muse 的生图任务所用 API。用户先后补充两种阻塞：连接失败后反复重试，以及等待 Muse 的域名访问授权。后者尚未获准执行，不能当成 HTTP 超时处理。用户回传的平台核实结果为“仅当前任务暂停，其他任务能继续”；应隔离等待授权的任务，持续派发其他独立消息。网络失败的具体原因仍单独核查。

本规则适用于生图、模型列表、联网测试等外部任务。它是 Muse 执行者和调度者的契约，不是桥内置的生图客户端；桥不能拦截 Muse 绕过 helper 自行执行的 curl/工具调用。必须将本规则接入真实主代理与子任务指令，并做手机验收。

## 调度者持续接收，执行者独立等待

主代理只领取、保存私密交接、判断依赖并派发原生子任务，不在调度循环里连接 API、同步等待或反复排查。每个独立任务由自己的执行者调用 API、正常续租、核对结果并直接回微信。其他独立消息继续派发，谁完成谁回复；不等生图结束，也不为整个聊天保持领取顺序。

各原生执行者可按 [后台工具流程](BURST_MESSAGES.md) 使用 tool-job 管理可信网络脚本并查询结果。后台脚本只能执行工具，不能冒充 Muse 模型任务。原生派发未接通应明确报告，不能自动用单模型加后台脚本代替用户选择的并行值守。已在同步 curl 中的串行子代理不会因改一条桥配置就变成并行调度者，须按 [主代理交接](NATIVE_PARALLEL.md) 实际切换。

## 域名授权只暂停相关任务

主调度者不执行可能触发域名授权的外部访问，也不等待某个执行者的授权结果。独立执行者遇到真实授权提示后，停止该操作的新尝试，保留原任务和提示；不换域名、代理、工具或执行者来绕过授权。把域名发进微信、让 Muse 帮忙连接，不等于已经通过 Muse 的原生权限检查。

1. 在私密调度台账记录 `waiting_for_authorization`、event/task 归属、所需域名和操作类型、检测 UTC 时间、原生授权标识及状态（平台实际提供时才填，否则记未提供），关联原交接文件。不要记录含密钥的 URL 或提示全文。该状态只是台账约定，桥当前没有同名命令、checkpoint phase 或授权批准接口；checkpoint 仍仅支持 started/completed。
2. 确认真实阻塞后，用本事件的稳定 `--progress --reply-id` 说明事实，例如“访问 example.com 需要在 Muse 中确认授权，此任务已暂停，未继续重试。”按授权阶段固定 ID，同阶段重试保持 ID 和正文一致；只在状态变化时反馈，不反复占位，不把此消息当成最终回复或提前 ack。若执行者已无法用工具，由仍可运行的调度者核实同一原生任务及所有权后，使用原交接 token 承担该事件的正常续租和这一稳定进度反馈；记录职责，不创建第二执行者，不代它调用外部 API。反馈路径不可用就记录未发送，不能声称手机已收到。
3. 调度者继续 `next → 私密交接 → 原生派发 → 继续 next`。等待授权的事件不占住全局派发循环；其他执行者完成即直接回复。续租仍须核实任务与授权等待真实存在，设置有界的等待复查/截止策略，不以无限续租掩盖死亡任务。无法续租时停止新操作并保留现场，不清租约或从数据库取 token。
4. 授权仅在 Muse 实际提供的原生入口按用户选择处理；不把微信里的“同意”自动转成平台批准，不自动扩大白名单。原生批准后先核对任务、权限范围、有效租约、已有步骤和远端结果，再恢复尚未执行的操作；拒绝/撤销则停止该操作并如实反馈，未决外部效果先核对。不能因授权结束或租约到期就盲目重新生图。

授权等待与 HTTP 预算分别记录，批准后沿用原尝试记录；先验证平台的暂停范围，自动派发和等待期间反馈须单独验收。

## 次数和总耗时都要有上限

以下为新任务的建议初始预算，写入本任务私密记录后执行；不是已在云端生效的配置，也不保证上游必能在预算内完成。

| 操作 | 初始边界 | 到达边界后 |
| --- | --- | --- |
| 建立连接 | 每次连接超时5秒 | 记录实际失败阶段，不无限等待 |
| 无副作用的连通性/模型列表查询 | 每次最多20秒；瞬态故障最多额外重试1次；含退避总共不超过45秒 | 返回已核实失败，不继续换域名、换工具、换班重试 |
| 发起生图等可能计费/创建远端任务的请求 | 默认只提交1次；本地执行预算初始120秒，包含请求、等待与已有任务的状态查询 | 超时不重新提交。先查原远端任务或幂等键；结果未知则记录待核对 |

认证/权限失败、目标路径或参数错误不做自动重试。只读请求的瞬态故障重试仍须满足剩余总预算；429按服务端退避提示处理，等待将超预算则结束本轮。不得把一个外部错误反复当成新任务：相同事件/步骤的尝试次数、开始时间、截止时间和原远端任务ID应持久化，换班、换工具或新建job不得重置预算。只读查询重试和有副作用的重新提交是不同操作，不能互相套用策略。

确实需要更久的生成任务，可在执行前根据服务接口和用户要求设定有界预算并记录原因；不能在连续失败时自动一次次延长。异步生成优先保存远端任务ID后有限轮询，不能反复新建生成任务。截止后不再发起新操作；后续核对作为有记录的独立跟进，不占住全局调度循环。

通过 tool-job 执行时，监督器的 --timeout 设置为整段脚本预算（只读诊断45s、生图初始120s），而非每次请求预算；脚本内部也要限制次数与截止。已有监督器会终止超时的本地进程组且不会自动重跑，但这不能撤销远端已发生的动作，也不能阻止模型在监督器外再次调用 API。

## 失败反馈与结果核对

微信只发纯文本真实结果，不发占位确认。确认连接失败、鉴权失败或已到截止时，给出对应实际结果，不先花十分钟继续试验。已确认失败且步骤可安全结清时记录真实失败并最终回复；远端效果未知或started尚待核对时，先用稳定progress说明已核实的超时和“结果未确认、已停止重试”，保留原交接与步骤，不自动completed或提前ack。反馈之后调度者仍继续处理其他消息。

未收到生成响应不能直接说“没有生成”或“不会扣费”。已有远端ID、幂等键和产物要先核对；不换ID重做。API凭据不放命令参数、公共日志或任务标题，不为排查切换未授权主机。外部API当前的暂停重测边界见 [运行环境恢复](RUNTIME_RECOVERY.md)，本规则不授权重新连接或生图。

## 用无副作用任务验证

在隔离任务中使用本地模拟端点返回超时/临时失败，记录尝试次数及总耗时；不调用真实生图API。长任务进行时，从微信连发编号短消息，主聊天不人工介入，核对短任务在长任务结束前已经开始并回复。再核对失败任务到预算后停止、产生对应结果/待核对反馈，同一任务没有因换班或换工具继续新建尝试。保存真实任务handle、event/request关联与UTC时刻；人工救援和本地mock都不能代替自动派发验收。

授权隔离验收使用已经存在的原生待授权状态，不再请求目标域名制造提示，也不调用真实生图。先用无副作用本地短任务核对其他任务仍可运行；再仅从微信发送独立编号消息，要求自动领取、真实派发并在原授权尚未处理时回复。保存等待状态、短任务 handle、领取/开始/accepted/手机时刻及人工介入情况。无待授权样本就记未执行；人工打开主聊天才能派发则自动链路失败。完整执行步骤见[授权阻塞修复指令](给Muse修复域名授权阻塞的指令.txt)。
