# 常驻 Muse worker 池

当前模式是多个真实 Muse 原生 worker 持续直接领取、各自处理并回复。主代理负责启动、查询、补位和换班，不再为每条消息领取及派发。旧的“每条消息等 hook 唤醒主代理，再创建执行者”不作为日常消费路径。

直接执行 [恢复常驻 worker 的完整指令](给Muse恢复常驻worker的指令.txt)。已有健康 rc.5 桥可用，不必升级、重启或重新扫码。本仓库没有 Muse 原生任务创建 API；安装桥或阅读指令不会自动启动模型任务。

## 消息路径与容量

`微信 → 桥持久化 → 空闲常驻 worker 原子 next → 本 worker 处理 → 本事件 reply → 继续 next`。

默认目标为 6 个真实原生常驻 worker，每个一次 --limit 1。它是可调整的池大小，不是平台硬限制。每个 worker 对自己的事件逐个处理，池整体最多同时执行 6 个独立任务。B 先完成就先提交 B，不按领取序号缓存回复，也不交主代理统一转发。实际发包仍受微信接口和桥发送通道约束。

所有 worker 忙时，新消息仍会在持久化队列等待；6 个空闲 worker 接到同时到达的 10 个独立任务时，最多 6 个执行、4 个等待，任意一个完成便继续领取下一条，不等整批结束。空闲者继续领取，不等新 hook。扩到 6 个时核对实际 CPU、RSS、上游限流和任务状态，不能以标称内存承诺无限并发。本地 CPU 密集工具仍共用一个活动名额，远端推理和网络等待可重叠；工具队列数量不等于模型 worker 数量。

--wait 35s 是无消息时的长轮询上限，新事件到达会提前返回，不是每条固定延迟 35 秒。有异步回执、工具结果或续租截止时用短等待，例如 --wait 1s，按时检查维护。

## 职责与所有权

- 主代理使用平台真实工具创建、查询原生任务，为每个 slot 记录真实 handle、启动时间、私密目录和状态。只有主代理能派生也可使用此模式：worker 自身能 next/reply 即可，无需再派生。
- worker 持续消费，空 tasks 或完成一条不结束班次。空队列继续有界长轮询，不忙等；失败保留证据并退避。后台 shell、Node 子进程或 Promise.all 不能冒充多个 Muse worker。
- 不加全局唯一 next 者锁。桥在事务中原子领取，不同 worker 获得不同事件和独立 token；同一事件仍只有一个实际执行者。固定检测脚本和诊断探针仍只读，不消费业务消息。
- 每个 worker 独占 0700 父目录，每次领取保存新的 0600 原始交接文件。不共用可覆盖的 current-task/token 文件，不把凭据、正文、token 放入公共标题、日志或仓库。
- 不用“health 成功才 next”阻断整个池。backlog/claim_gap 可能正需要恢复消费；按具体故障范围处置，登录失效、恢复审查、停服及真实资源闸门仍须遵守。

## 事件协议

rc.5 用 muse next --limit 1 --lease 30m --wait 35s --output '/本次新私密目录/task.json'，先保存原响应再处理，不只靠聊天记 token。--output-dir 和本地候选 --task-file 必须先核对实际 CLI 帮助，不能凭版本号假定已部署。领取示例与空响应维护见完整恢复指令及 [MUSE.md](MUSE.md)。

读取 execution、completion 和稳定 request_id；unknown/rejected、未决 started 或需要 review 先核对，不重做外部动作。reply/renew/checkpoint/ack 均用本事件的完整原 token，每 5 分钟正常 renew 到 30 分钟。续租失败停止新操作，不从数据库抄 token、清租约或继续使用旧 token。

对外部副作用、昂贵或不可盲目重做的工具，以稳定 step 先 started，核实结果后 completed；cached 结果复用。超时不能自动 completed，接管须核对真实结果并按协议 reviewed。租约不能撤销已提交到外部的生图、付款或部署。

结果准备好直接 muse reply，accepted 后自动 ack。媒体可 --async，先保存原正文、文件路径和稳定 request_id；pending 不代表微信收到，仍需续租及查原回执，unknown 不自动重发。只有明确保存并持续维护旧事件时才能继续 next，不能遗弃旧事件或无限预领。

微信只发纯文本真实结果，不发“收到，正在处理”等占位。实质阶段结果或已核实阻塞才用稳定 --progress --reply-id，不提前 ack。较晚完成的长任务指出对应原请求，不等其他更早任务。

## 长任务、授权和依赖

外部 API 遵守 [EXTERNAL_API_TASKS.md](EXTERNAL_API_TASKS.md) 的尝试次数与整段截止。一个 worker 等网络或授权时，其余空闲 worker 继续直接领取。全池都被占用仍会排队，不能承诺绝无阻塞。

平台是否仅暂停当前任务、授权状态能否读取、独立反馈能否发送须分别核实。本仓库没有原生授权批准或取消接口；暂停者可能无法发微信或续租。观察/反馈须有经验证的独立运行角色，没有则标未接入，不能让第二执行者重做外部动作。见 [授权隔离指令](给Muse修复域名授权阻塞的指令.txt)。

“接着刚才”“取消”、同文件修改或同部署等事件，先关联原任务和共享状态后协调。原子领取只隔离同一事件，不能阻止不同事件重复调用同一外部操作；仍需自己的幂等标识及共享操作台账。局部协调不扩成整个聊天 FIFO，依赖不明先澄清。

## 轮换和恢复

先核对现有执行者与交接，仅补齐目标 6 个 slot 中缺失的常驻者。已有 3 个健康常驻者时保留它们，只新增另外 3 个，不重新创建整池；无池时才建立 6 个。创建并确认新 worker 已进入循环后，才停止旧的每条派发职责。原已领取事件保留原所有者；多个领取者可短暂共存且只领取新事件，不必全局暂停 next。不能先停所有消费者再等未经验证的 hook。

slot 换班先启动并确认新 worker，再令旧者停止新 next、完成或安全交接持有事件后退出。创建回执不明先查真实任务，不盲目重复补位。同一事件转移前确认旧执行者及工具已停止，沿用原交接和正常 renew；缺 token 等合法到期，不从数据库抄取。

常驻表示持续消费，不表示平台任务永不结束。刷新可能终止全部进程和原生任务；目录存在不等于存活。主代理须有真实可用的启动/补位入口；未验证则报告“刷新后自动恢复未接入”。同一慢 hook 只能作恢复提示，不能宣称独立可靠看门狗。见 [自动唤醒与交接](AUTOMATIC_DISPATCH.md) 和 [运行环境恢复](RUNTIME_RECOVERY.md)。

## 验收

1. 主代理启动池后不再人工操作；微信分两批发送独立编号消息，两批均由同一组常驻 handle 自动领取和回复，不靠每条新 spawn。每个 handle 可对应多个不同事件。
2. 一分钟连发 10 条，逐条核对缺失、重复、错配及入库/领取/开始/提交/accepted/手机时间，记录池大小与实际等待。队列空不等于手机全收到。
   在无副作用任务中另外验证 6 个真实 handle 的处理窗口重叠；槽全忙时后续事件等待，任一槽空闲立即补位，不按批次等待。6 个真实任务的资源和平台额度仍须部署环境实测，本地模拟不能证明云端容量。
3. 一个 worker 执行 90 秒无副作用等待时，其他 worker 自动领取短消息并在它完成前回复。已有授权等待单独验收，不重试真实 API 制造提示。
4. 轮换一个 slot 不停全池、不重复回复；刷新后的恢复另记通过/失败/未执行，人工主聊天救援不算自动通过。

本地 HTTP/SQLite 模拟只验证桥支持持续多消费者、租约隔离和完成顺序，不能证明 Muse 原生常驻、平台恢复或手机收取通过。
