请把当前微信桥 Muse Link 从 v0.2.1 升级到上传的 v0.3.0，增加“你生成图片或视频后，直接回传当前微信”的能力。保留原账号、token、配置、SQLite 收件箱与发送记录；已有会话健康时无需重新扫码。

先读包内 docs/MUSE.md 的升级步骤、docs/MEDIA.md 和 docs/API.md。处理完已领取任务或持久化进度后，暂停原生微信 hook，停止 muse-link 服务，再从新解压目录执行 bash deploy/install.sh。只保留一套接收进程，不删除或重建旧数据库。

将你生成工具实际输出目录加入 ~/.config/muse-link/config.json 的 media_roots，保留其他字段；默认只允许 ~/workspace。文件必须在你云端、已完整生成并能由服务用户读取；如果生成工具只返回媒体 ID、预览或 URL，先通过实际 Muse 工具导出原文件。图片支持 PNG/JPEG/GIF/WebP，单张 20 MiB；视频支持 MP4/MOV 容器，单个 50 MiB，不转码，优先 H.264/AAC MP4。

启动/重启服务并检查 muse-link health、muse-link status。status 必须显示 version=0.3.0，capabilities.send 包含 image、video；只有新 CLI --help 不算后台已升级。更新原 hook，替换旧版“只能纯文字”的指令，使用 docs/MUSE.md 中完整任务指令，dry_run 后启用并记录实际检测间隔。

Muse worker 领取事件后，长任务先用 --progress --reply-id started 发简短文字确认。生成完图片/视频，在同一最终命令发送所有结果，例如 muse-link muse reply '<实际 event_id>' --image '/实际绝对路径/result.png' --video '/实际绝对路径/result.mp4'；可再带 --text - 从 stdin 传说明。最多 4 个媒体，可仅发图片或视频。不能先发最终文字完成事件，再试图补图；预览图使用 --progress --reply-id preview。

调用返回 accepted 只代表微信接口确认，全部消息确认后自动完成事件。上传或文件准备失败返回 failed、retryable=true，核对原因后可用原请求、原文字和原媒体路径续传，已确认的消息不会再发；unknown/rejected 先报告核对，不换 ID 盲目重试，不重新生成整项任务。当前仍不支持读取微信发来的图片/视频、普通文件和原始语音。
