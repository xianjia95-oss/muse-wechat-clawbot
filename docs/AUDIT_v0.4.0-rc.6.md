# rc.6 候选版的本地审计与冒烟

2026-10-22。项目：https://github.com/xianjia95-oss/muse-wechat-clawbot 。本轮在本地检查含既有并发队列及原生并行接入文档的 rc.6 候选源码，未发布 Release、未部署云端。源码提交不等于完成云端升级或生产验收；报告仅列可确认的问题和验收边界。

## 发现与修复

| 问题 | 影响 | 当前处理 |
| --- | --- | --- |
| P2：先创建可见 job 目录，再写 job.json | 两步之间中断会留下缺失元数据的任务，后续 list/pending/dispatch 抛错 | 在私密隐藏目录写完并同步元数据，原子重命名后同步父目录，再授权执行；未发布记录不能启动脚本 |
| P2：稳定 ID 查缓存前检查原脚本存在 | 已完成/失败工具的脚本被清理后，查询报 ENOENT，不能读取原结果 | 先核对已有 ID 的路径、超时、类别并返回缓存；仅新任务检查脚本，不重跑旧 ID |
| P2：文件引用与实际文件缺少完整落盘顺序 | 断电时数据库可能保留媒体引用而文件未持久化；备份/恢复或交接可能缺少目录项持久化保证 | 媒体先同步密文、发布文件名并同步目录再保存引用；备份/恢复先同步暂存树再发布并同步父目录；交接文件领取前同步目录 |
| P2：取消标记的排他创建竞争 | 同时取消时一方可能收到 EEXIST，虽然取消已经请求 | 将 EEXIST 视为已请求，保留其他磁盘错误；不更改事件确认状态 |

没有新增运行依赖。保留独立事件 token 校验、稳定回复 ID、unknown 不自动重发、工具执行前持久化身份/许可屏障、恢复后人工核对闸门。

新增落盘辅助函数的 Windows 短路径循环问题也在本轮验证中发现并修复：Windows 不尝试目录 fsync，路径统一为绝对路径且遍历在根目录停止。Windows 的文件同步仍执行；Linux 专用监督器继续仅在 Linux 运行。

## 仍需处理的部署边界

1. **原生任务调度接入**：当前仓库给出协议和部署指令；实际创建、确认接管及查询原生任务必须使用 Muse 环境真实工具。仅升级 daemon 或配置 tool-job 并发不会让模型 worker 自动并行。须回传真实 task handle、交接记录及并行开始/直接回复时间。
2. **手机和长期验收**：本轮没有云端连接。真实连续 10 条消息、长任务不挡短回复、图片/视频手机收取及播放、换班恢复和 72 小时观测尚未完成。accepted 只表示微信 API 接受，不能证明手机显示。
3. **已有异常记录**：新发布流程防止新增缺失元数据的可见 job 目录；旧版本已留下的缺失/损坏记录不会被自动忽略或删除，仍须核对进程与外部结果。隐藏暂存目录保留供检查，不能把任意未知目录当成安全重试依据。
4. **有界历史容量**：工具池全部状态合计保留 256 条，settle 只结清通知，不释放历史容量；到上限会拒绝新任务，不能无期限运行而不维护。归档必须先核对已终止并保留业务事件/checkpoint/结果账本，移走记录会失去 helper 对该旧 ID 的去重；禁止通过新 ID/删锁绕过。工具目录不包含在桥 SQLite 备份中，需独立私密备份。
5. **持久化边界**：fsync 和重命名顺序修复通过故障注入验证，没有做真实断电测试；仍要求本地持久化文件系统正确实现同步和 SQLite 锁。备份/恢复若最终重命名后父目录同步失败会返回错误，目录可能已经切换；先检查目标与 pre-restore 记录，不能据报错就盲目重跑。
6. **入站附件能力**：目前可把 Muse 本地生成的图片/视频发回微信；从微信发来的图片、视频和文件仍不下载或交给模型识别，仅报告不支持。语音仅使用协议已给出的转写文本，不包含本地语音识别。这是既有功能边界，不能按“全部媒体双向支持”验收。

本轮已通过本地代码、回归和安装冒烟检查；该部署尚不能宣布完成生产验收。按 [生产验收](PRODUCTION.md) 与 [原生并行指令](给Muse启用原生并行任务的指令.txt) 完成真实链路后再作判断。
