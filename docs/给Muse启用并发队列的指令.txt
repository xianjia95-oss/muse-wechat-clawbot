本文件用于 Muse Link v0.4.0-rc.6 的后台工具资源控制，以及缺少原生并行时的单模型保底。当前 Muse 环境已反馈能派发并行任务，优先执行 docs/给Muse启用原生并行任务的指令.txt：一个轻量调度者加多个独立执行者。下面的4个工具名额不是Muse任务数量上限；不能只改后台脚本就声称已实现Muse任务并行。先读 docs/BURST_MESSAGES.md、docs/MUSE.md、docs/PRODUCTION.md。不要重跑内存压力测试，不上传本地内存工具、报告或凭据。

升级前暂停新任务调度，完成当前工具或核对其进程和外部结果，保存原领取文件/步骤/job/结果/回执的私密交接。依照 docs/给Muse升级的指令.txt 升级服务与配套 helper/hook，保留微信登录、配置、SQLite、原 job ID 和记录，不清租约、不删锁、不批量 ack。旧 supervisor 继续使用旧策略，需完成并核对后再启用新调度。status.version 必须是 0.4.0-rc.6；本地版本号不能代替运行中 daemon 版本。

从实际新安装路径执行（服务账号与真实 worker 同 HOME）：

JOB_HELPER="$HOME/.local/share/muse-link/current/scripts/tool-job.mjs"
JOBS="$HOME/.local/state/muse-link-worker/jobs"
node "$JOB_HELPER" configure --dir "$JOBS" --max-active 4 --max-io 4 --max-cpu 1 --max-queued 64
node "$JOB_HELPER" status --dir "$JOBS"

确认 limits 为 4/4/1/64。配置保存在该 job 根目录的私密 .scheduler.json，不放桥 config.json。全局 4 表示运行中的网络与计算合计最多 4，不是 4+1；网络等待归 io，本地计算归 cpu，混合/不确定归 cpu。分类不限制真实 CPU 使用，脚本不另起脱离监督进程组的守护进程。两核机先采用这一档，不直接开 10 个密集计算进程；更高网络并发待真实连续消息验收后再调整。

把以下流程写入并实际执行于原生 hook 的 worker 指令，只替换 daemon 不会生效：

1. 每轮先检查全部未完成事件，按原协议每 5 分钟正常 renew 到 30 分钟并保存返回的 lease_until。只有 renew 成功，才对对应 queued job 执行 refresh --id '<原稳定job>' --start-before '<新lease_until减60秒的UTC ISO时间>'。后台目录不保存 token，监督器不能自行验证/续租事件；续租失败停止新操作、取消尚在队列中的工具，核对已经执行的外部动作，不抢租约、不换 ID。
2. node "$JOB_HELPER" dispatch --dir "$JOBS"；检查 list 的未结清终态与原 request 回执，核对实际产物后完成原 checkpoint，再用原事件有效 token 最终 reply。媒体用 --async，submitted/pending 立即回到循环，accepted 才 settle；不因短消息持续进来而饿死完成结果。
3. 继续 muse next --limit 1 --lease 30m --output '<新的私密claim目录>/task.json'。有后台任务/异步发送时 --wait 1s，全空闲时才长等待或交给 hook。一次取一条不妨碍后台多个工具并发。短文字直接处理和回复，长任务先 progress，私密保存事件、稳定步骤、job ID、脚本、结果和原完成 request_id，不提前 ack。
4. 原本需要 checkpoint 的操作仍先 started。在权限范围内准备独立可信 .mjs 脚本，排队/运行期间不得改写；不将微信正文拼接为可执行命令，不将 API key 放参数或日志。用 enqueue --dir "$JOBS" --id '<稳定编号>' --kind io --script '/实际私密脚本.mjs' --timeout 120s --start-before '<当前lease_until减60秒的UTC ISO时间>'。计算任务改 --kind cpu。启动截止必须在未来一小时内，不能只按本机当前时间任意延长。enqueue 返回后不等待工具退出，立即继续下一轮。
5. queued、starting、running 都未完成，不确认事件。完成一个工具后监督器自动补位；每轮 dispatch 补偿中断/策略变更。队列超过 64 或全部记录达到 256 时，保留原交接和同一 job ID，说明排队原因，稍后核对重试。相同 ID 重复 enqueue 只读缓存，不重跑、不续期。取消/过期不会复活；未执行的 started 步骤仍须核对后按 reviewed 流程结清，不自动伪造成功。
6. 独立任务谁完成谁回复，长任务指出对应原请求。涉及追问、改指令、取消和同一资源修改时按上下文/依赖协调，不盲目并发。不要新建多个 worker 共用同一领取文件；hook 检测是只读，不能在检测阶段 dispatch/领取。调整额外的 90 秒去重，保持新消息、可运行队列和完成结果能唤醒原循环。先 dry_run 再 enable 并确认真实间隔。

验收先用无副作用的本地等待/本地 HTTP 模拟脚本，不调用真实生图、不制造未知外部操作：

- 在隔离私密 job 目录中提交 10 个不同稳定 ID 的任务，含 io/cpu，观察最多 4 个活动、cpu 最多 1；后续任务 queued，完成自动补位，10 个均有对应结果。再次提交同一 ID 不再次执行。隔离测试截止不关联真实事件时明确记录为测试许可，不能照搬给业务任务。
- 手机 1 分钟内连发 10 条有编号消息，混合短问答与已授权的等待任务。逐条保存 received、submit、accepted、手机时间及对应 job，不以 pending=0 断言全收到。短回复不等待长工具全部完成；不承诺固定秒数。
- 验证队列满时保留原任务、排队取消/到期不执行、续租成功后 refresh、故障后原 ID 恢复、空 inbox 下可运行队列/完成结果唤醒。重启测试前核对当前工具状态，不重复外部动作，不直接改生产 job.json 模拟故障。
- 回传脱敏结果表及 CPU/RSS/磁盘、排队等待、失败数和重复执行数，不回传正文/token/日志原文。若瓶颈是 Muse 推理或平台唤醒，明确单模型仍有限制，再验证平台是否提供独立模型任务接口；不能用增加后台工具进程冒充模型并行。

本候选版尚需真实 Muse 与手机验收。回滚到 rc.5 前停止新增任务，排空或明确取消 queued，核对所有活动工具、未决步骤与回执，保留业务去重和私密记录，切换匹配 helper/worker；旧版不支持 queued。不要为回滚直接删除队列、锁或已使用 ID。
