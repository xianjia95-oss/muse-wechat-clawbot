请由 Meta Muse 主代理执行：恢复或扩容为 6 个真实常驻 Muse worker 直接轮询微信桥，不再让每条消息等 hook 唤醒主代理后派发。完成即直接回复，后续据实际负载调节。每个 worker 一次领一条、处理后继续领；整体最多6个独立任务并行，所有 worker 忙时仍会排队。

本指令配套候选源码，仍须在真实Muse云端验收。旧标签、旧下载包或云端缓存文档可能仍是逐条派发方案；本次恢复以本指令为准。读取同一提交的配套文档，不因读取源码就运行安装器或覆盖在线部署。缺少新文档时先按下方完整协议恢复，不退回旧方案；源码可获取不代表候选版已正式发布或部署。

这是运行协议调整，现有健康 rc.5 桥可用。不要因为新指令就升级、重启或重新扫码；不要推送仓库、发布或上传本地调试材料。新参数先核对实际 CLI 帮助。不要重试已暂停的外部 API、生图或内存压力测试，不扩大域名权限。

一、核对能力和已有归属
读 docs/NATIVE_PARALLEL.md、docs/MUSE.md、docs/RUNTIME_RECOVERY.md。只读记录 CLI/后台版本、status、health、ready/leased、真实运行任务及原私密交接。backlog/claim_gap 不禁止所有 next；登录失效、恢复审查、主动停服及真实资源限制单独处理。

主代理使用真实平台创建/查询工具；子任务只需能 next/reply/renew/checkpoint，无须再次派生。用真实 task handle，不用 shell 后台进程、Node 或“承诺已启动”代替 Muse worker。

二、不留空窗地建池
目标为6个稳定活动slot。先查询真实原生任务并核对私密台账，只补齐缺失slot；若已有3个健康常驻worker，保留原3个及其目录，仅新增3个；若尚无池才建立6个，不先停旧者或重新创建整池。新slot在私密0700根目录下各建新目录，台账0600记录slot、真实handle、启动UTC、状态、持有事件及原交接路径。真实标识只留私密报告，不进公共标题、日志或仓库。创建中/结果未知先查询，不能盲目重复创建。

以worker-1至worker-6标识6个slot，使用真实原生工具仅创建缺失的worker，完整附上第三节协议；已有slot沿用真实handle，不因名称相同就认定存活。逐个确认真实运行、有工具权限、进入直接next循环，最终记录6个不同handle。不加全局唯一领取者锁，桥原子领取会隔离新事件。

至少一个新worker进入循环且成功领取/回复无副作用测试事件后，才停止旧的每条消息主级派发职责。尚有旧常驻者时逐个换班，不停全池。原已领取事件仍由原所有者负责，不抢租约、不重复派发；旧者停止新next后先收尾或安全交接再退出。不能先停所有消费者再等wake。

三、完整附给每个常驻worker的协议
你是常驻微信消费者，不是单轮探针。持续执行“检查自己未决事件/续租/回执 → next → 保存原始领取 → 处理本事件 → 直接reply → 再next”。不让主代理逐条派发，不等新hook，不等其他worker。空tasks继续有界长轮询，不因完成一条或空队列结束班次；错误保留证据并退避，不忙等。

全空闲时--wait 35s，新消息会提前返回；有异步回执、工具或续租截止时--wait 1s并及时维护。--limit 1是单次领取量，不是全局串行限制。不一次预领整个队列，不把工具名额当模型worker数量。

rc.5每次在自己的独占私密目录新建claim目录。下面仅示范一次领取，由真实Muse worker反复执行完整处理循环，不包成只领取不处理的无限shell循环。替换为本slot实际绝对目录；先核对路径及父目录非符号链接、属主、0700权限，不共用目录：

umask 077
CLAIM_DIR=$(mktemp -d '/absolute/private/worker-slot/claim.XXXXXXXX')
muse-link muse next --limit 1 --lease 30m --wait 35s \
  --output "$CLAIM_DIR/task.json" \
  > "$CLAIM_DIR/response.json" 2> "$CLAIM_DIR/command.stderr"

保存该命令的真实退出码，三个文件仅私密读取，不整份贴到聊天。非零退出、awaiting_response、不完整或身份变化时保留现场，不当空领取。保存受控错误字段，不把token/正文打印到工具日志。

只有本次命令成功且原文件完整response_saved、tasks=[]时，才可核对本次独占目录/文件身份后逐个unlink本次已知空响应文件，再rmdir空目录；有额外文件或归属不明则保留。禁止glob批删、rm -rf或清别的worker目录，非空事件交接不可删除。该维护不阻塞其他worker。空领取清理未核实时保留并记录数量，另行受控维护，不能静默无限堆积。

实际CLI帮助有--output-dir时，可由它管理本slot的claims目录；从非空handoff_file读原领取，空响应handoff_file=null。帮助无--task-file时，reply/renew/checkpoint用原领取完整--lease-token，不截短、不写死、不取数据库token。不能凭文档版本号假定已部署参数。

读取execution、completion及稳定request_id；保存event、完整token、lease_until、工具结果/文件路径。每5分钟用本事件原token正常renew到30分钟，长工具须有真实可用的续租路径。续租失败停止新操作，不无限后台续租掩盖死亡，不覆盖其他事件文件。

外部副作用、昂贵或不可盲目重做的操作先稳定checkpoint started，核实结果后completed；cached复用。遗留started/unknown先查真实工具和远端效果，按协议reviewed，不为回复虚标completed。普通问候不额外写工具步骤。不换ID重做结果未知的操作。

结果就绪立即用本event及完整token执行muse reply，稳定request_id、自动路由、accepted后自动ack。直接回微信，不交主代理等待转发，不等更早事件。正文从stdin安全传入，不拼shell代码。微信纯文本真实结果，不发“收到，正在处理”等占位；实质结果或已核实阻塞才用稳定progress/reply-id，不提前ack。

媒体可--async，先保存正文、路径及稳定request_id，pending后短轮询原回执并续租，accepted前不能丢交接或算完成。unknown不自动重发；可安全续传时同ID/内容，不重新生图。继续next时旧事件仍需明确维护，不能无限预领。

长任务/授权等待只占自己的处理槽，其余worker继续next/reply；不建全局等待锁。所有槽被占仍会排队。外部API按docs/EXTERNAL_API_TASKS.md：只读诊断最多额外重试1次、整段45秒；生图默认提交1次、初始整段120秒，确需更久在执行前设有界预算。换班/换工具不重置预算；暂停任务不因本指令获得重测授权。

原生授权不能绕过，未操作不等于拒绝。暂停者可能无法续租或发微信；主代理须核实独立观察/反馈路径，没有则标未接入，不能假定池自动提供授权通知。不给第二执行者外部执行权，不把微信“同意”当平台批准，不扩白名单、不换域名或代理。

追问、取消、同文件/部署修改先从私密共享台账关联原事件和handle，协调同资源操作。不同事件token不能防止同一外部操作重复执行，仍需幂等标识；局部依赖不扩成聊天FIFO。失败/结束保存持有事件、原请求与工具结果，便于唯一接管。

6个是原生消费者目标数，不是新增6个CPU密集进程或把后台工具名额改成6。本地CPU密集工具仍共用最多1个活动名额，其他工具资源策略保留。扩容时记录真实CPU/RSS和平台额度/限流；平台拒绝或资源不足如实保留原因，不宣称已到6个，不强行重试派生，也不停止原健康slot。

四、维护与恢复边界
主代理结束当前回合后，池仍在真实原生任务中持续消费。记录真实slot/handle及状态；空领取不是死亡，agents残留不是存活。按平台实际任务期限换班，不编造永久在线保证。

换一个slot先创建并确认新常驻者，再令旧者停新next并收尾，其他slot继续。事件接管前确认旧执行者/工具停止，用原交接和正常renew接续；缺token等合法到期，不清租约、不抄数据库。accepted不再发，started/unknown先核对。

hook保留只读检测、告警与启动/补位提示，不作为每条消息必经入口。HATCH_HOOK_RESULT适配一次单结果，先dry_run；探针不next或删claim。刷新杀死所有任务时，按docs/RUNTIME_RECOVERY.md恢复唯一桥、对账并重建池。须有真实、独立于失效wake路径的主级启动入口；没有则明确“刷新后自动恢复未接入”，不能以常驻消费正常冒充刷新验收通过。

五、切换后验收（主聊天无人操作）
1. 启动池后停止人工介入，微信分两批发独立编号消息；第二批仍由原常驻handle处理，证明不是单轮或逐条人工spawn。
2. 一分钟连发10条不同编号，每条私密记录event、slot/handle、入库/领取/开始/提交/accepted/手机UTC时刻及等待；缺失0、重复0、错配0。6个空闲worker最多先处理6条，剩余4条在槽释放后立即补位，不等整批完成，不宣称10条同时执行。另用无副作用等待任务验证6个真实handle的处理窗口重叠，单列资源用量与平台限流；本地模拟不替代这一项。
3. 一个worker执行90秒无副作用等待，其间其他worker领取短消息、在长任务结束前回复。已有授权等待单独测，不访问真实API制造提示。
4. 逐个换一个slot，其他slot持续回复。刷新自动恢复另做受控验收，无入口记未接入，不强制刷新业务环境。

只回脱敏汇总：实际池大小/状态、工具名称、通过/失败/未执行、时延统计、人工介入与剩余风险。真实handle及逐事件证据仅留私密报告。当前本地改动未经用户验证，不推送、不发布。
