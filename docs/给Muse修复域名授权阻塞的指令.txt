执行入口：具备原生任务创建与查询权限的 Meta Muse 主代理。

先读 docs/EXTERNAL_API_TASKS.md、docs/NATIVE_PARALLEL.md、docs/AUTOMATIC_DISPATCH.md。这是通用接入指令，不包含真实域名、凭据、任务标识或现场日志，也不授权访问任何示例主机。

一、核对并接管待办
读取status/health/diagnose及真实池任务状态，核对私密交接。ready无人领取时，由主代理按docs/给Muse恢复常驻worker的指令.txt恢复多个直接next/reply的常驻消费者，不再逐条主级派发。已领取事件保留原所有者，创建未知先查，不清租约、不抄数据库token。人工恢复不算自动通过。

只读限制适用于检测脚本和诊断探针，不约束真实常驻消费者的next/reply。healthy 不等于没有待办；worker_backlog 等告警可能正需要恢复领取。按具体故障范围处理，保留登录、恢复审查、资源闸门和租约保护，不笼统忽略所有 503。

二、隔离授权等待
受控访问只留在领取本事件的worker，主代理不访问也不等待授权。其他空闲常驻worker继续next/reply，无需派生子任务或等待主代理。全池都被占仍会排队；常驻池不自动提供授权反馈。

在发起可能受控的访问之前，保存原私密交接与真实 handle，实际接通独立的观察、续租和反馈路径。不能假设已暂停的执行者还能执行下一条记录或回复命令。先核实平台是否只暂停当前任务；若是全局暂停，明确隔离不支持或未核实。

确有原生授权证据并关联本事件时，私密台账记 waiting_for_authorization、事件与 handle、所需域名/操作、UTC 时刻及平台真实提供的授权标识。不要保存提示全文或带密钥 URL。这只是台账约定，不是 CLI 命令或 checkpoint phase。

仍能运行的调度侧核实任务与所有权后，可用原交接承担正常续租和稳定 progress，说明已核实的具体阻塞，不创建第二执行者、不代它访问 API、不提前 ack。设置有界复查和截止，不能无限续租掩盖任务死亡。反馈不可用就记未发送，不声称手机收到。

无法读取原生待授权状态、只能看到 running 时，记原因未知。可按事先约定的反馈截止发送真实超时说明，但不能猜成授权拒绝、HTTP 超时或已取消。桥没有原生权限回调或取消接口，写台账不等于自动反馈已接入。

三、尊重原生授权与任务范围
未操作弹窗不等于拒绝。批准、拒绝和撤销只以原生真实结果为准；不代用户点击、不扩大白名单、不把微信同意自动转为平台批准，不换域名、代理、工具或任务绕过权限检查。

批准后核对权限范围、有效租约、既有步骤和远端结果，再继续未执行的动作。明确拒绝后停止该操作并如实反馈；有未决副作用先核对，不能自动 completed 或提前 ack。等待授权不重置原网络尝试预算。

实际主机和凭据只从本事件私密原始指令取得，不从公开示例或旧事件复制。模型列表任务不扩展为生图。暂停任务不因本指令自动获得重测授权。

四、租约与执行者结束核对
失败须保留脱敏退出码、error/lease_reason/server_time/lease_until 和原稳定 request_id。文字报告不能代替真实桥回执，不将失败命令、token 或正文写入公共文档。

执行者结束而 final 未 accepted 时，核对原请求、实际工具及远端结果，确认旧执行者停止后再指定唯一责任人。沿用原私密交接和完整 token，不手工截短、不取数据库 token、不换 ID 重做操作。已 accepted 的结果不重复发送。

本地候选 CLI 的 muse reply/renew/checkpoint 支持 --task-file 读取原领取文件中的完整 token，仍须显式 event_id 和同一配置/后台；先核对实际安装版本。它不恢复失效权限，也不提供自动接管。用户验证前不推送或升级部署。

五、验收
利用已有待授权状态，不访问域名制造提示。用户仅从微信发独立编号短消息，主聊天无人操作；核对授权未处理期间短消息由其他常驻worker自动领取并回复。保存私密阶段时间和 handle；60 秒未自动领取记失败，人工救援不算通过。

另验收原任务等待期间的微信反馈，以及用户自行拒绝后的安全收尾；未发生的情况记未执行，不代用户操作。原生状态不可读时的真实超时反馈不能冒充精确授权通知。交付只包含脱敏结论和必要汇总，不附真实域名、凭据、正文、handle 或原始日志。
