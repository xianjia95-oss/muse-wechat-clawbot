# 常驻 worker 池与环境刷新恢复

> 隐私说明：服务名称、外部主机及调用标识已作示例化处理；.example地址不可作为实际请求目标。实际目标与任务标识只能从部署环境的私密原始交接取得，不得从本文示例恢复或替换。

项目：https://github.com/xianjia95-oss/muse-wechat-clawbot

## 已确认的部署约束

部署前核实拟任主代理的原生创建/查询权限、子代理是否允许派生，以及环境刷新后各类文件、平台注册和任务是否保留。以下恢复流程按刷新可能终止全部进程与任务设计，不能把残留目录当成存活证据。

主代理负责创建、查询和维护真实常驻 worker 池；普通子任务直接 next/reply 并持续消费，无需派生。日常消息不再每条等待 hook 唤醒主代理。刷新后旧任务目录不是存活证据，systemd、cron和本地观察器也不保证跨整个环境刷新存活。

## 恢复常驻消费

完整执行 [恢复指令](给Muse恢复常驻worker的指令.txt)：核对现有所有者，先启动并确认初始3个真实worker，再结束旧消费职责。每个slot独占私密目录，原已领取事件继续由原所有者负责。逐slot换班，不停整个池；不从数据库取token或清有效租约。

空任务继续长轮询，完成一条继续领取；不等新hook或主代理派发。谁完成谁直接回复，所有槽忙时仍排队。原生授权、外部API预算和共享操作幂等继续遵守 [外部任务规则](EXTERNAL_API_TASKS.md)。

hook/探针只读检测与告警；wake到达主代理时用于查池及补位，不逐事件spawn。冷启动/刷新恢复必须接入实际存在、能触达主级创建能力的独立启动入口。没有则标“自动恢复未接入”，不能以当前池在运行推断刷新后会自动重建。

## 刷新后的恢复顺序

以下是主代理的恢复流程，不是可自动执行的平台注册 API。必须把该流程接入实际存在且经验证的刷新后启动入口；入口不存在或 hook 仍不能触达主代理时，如实标记“自动恢复未接入”。

1. **先读状态**：核对当前实例/刷新时间、项目和配置路径、SQLite 是否存在、状态锁、实际 daemon 与原生任务状态。旧目录/PID 文件不是进程存活证据，PID 也可能复用。已有健康桥时不重复启动，不重新扫码。脚本若需从备份恢复，保留真实平台输出适配。
2. **恢复唯一桥服务**：若确认原进程已停止且平台服务管理器仍可用，恢复原有服务注册、配置与代理环境后启动一次。若 systemd 已不可用，应使用平台真实提供的进程/启动管理入口，不能只因为有 systemctl 命令就认定存在 manager。CLI/daemon 版本分别核对；服务恢复后检查登录与至少一次轮询成功。
3. **对账未完成事件**：读取原始私密交接文件，查询对应原生 handle。只有平台确认旧任务已停止/终止后，才由主代理为该事件指定一个恢复执行者。创建结果未知先查询，不再创建一份；刷新后不要一律重派所有历史任务。
4. **接续原租约**：原 token 完整且仍有效时，使用原 token 正常 renew 后接续，不必机械等待 30 分钟；同一事件只有一个实际执行者。缺少原 token 时只能等待当前租约到期后正常领取，不能抄数据库 token、强制释放或修改截止。已 accepted 的最终回复只核对，不再发。
5. **核实外部效果**：刷新杀死本地进程，并不能撤销已提交到远端的生图、付款、部署等动作。started/unknown 或仍在远端执行的工具先查真实结果，不换 ID 重跑。原 lease 的工具正常结束可写 completed，包括已核实的失败结果；换租约或结果未知时须真实核对后 --reviewed，不能只为解除回复拦截打标。
6. **恢复常驻池**：主代理核对已接管事件后，使用真实原生工具重建多个直接 next/reply 的 worker。确认运行与持续消费，按事件正常续租及检查回执。不启动无限代死亡任务续租的 shell。仅轮换单个 slot 时，其余活跃者继续，不重派原事件。
7. **恢复观测并复验**：为本次观测使用新 UTC 时间戳的报告路径，保留旧段和重启缺口。自动发送任务只能来自真实待处理事件；从手机发一条编号测试，主聊天不人工介入，核对实际自动领取、回复和手机显示。手动恢复不能记作自动恢复通过。

桥 SQLite 备份不包含 worker 私密交接目录、工具账本、平台 hook 注册或原生任务状态；这些按各自的私密持久化/备份方案保留。观察器72小时记录跨刷新时，逐段标明开始/结束/缺口和恢复耗时，不能把不连续段拼成“无中断连续通过”。

## 告警、claim 和工具的处理

- `worker_claim_gap`/backlog：有ready却缺领取进展。先核对池中真实handle、slot状态、直接next记录及资源占用；全池已停止则查主级补位/启动入口。ready=0时查看lease/步骤/发送；不能只缩短hook间隔掩盖无人消费。
- `worker_lease_stalled`：未完成租约长时间没有活动，不等于微信网络故障或任务死亡。核对真实所有者、原交接、外部工具与正常续租，不清有效租约。
- `task_step_uncertain`/started：超时不自动completed。先核实实际工具和远端结果，按协议reviewed，不为最终回复跳过保护。已核实阻塞可用稳定progress，不提前ack。
- hook/诊断探针只读，不next、不清claim。rc.5每次新私密文件，已支持的--output-dir仅清本次确认空响应；旧目录核对归属后单独维护，不批删awaiting_response、不完整或非空记录。
- 告警记录只存受控故障码、UTC检测时间和队列计数，不保存含凭据的原始stderr。旧告警延迟到达时复查当前状态，不按旧reason重启；现有wrapper须显式合并检测器并dry_run。

## 外部 API 超时

外部任务由领取它的常驻worker处理，次数及整段截止见 [外部任务规则](EXTERNAL_API_TASKS.md)。其余空闲池员继续直接领取，主代理不等待网络诊断。

请求目标只取本事件的私密原始指令，不能从公开示例、旧事件或猜测恢复。模型列表查询不自动扩展为生图；未经允许不更换主机，不向其他主机发送凭据，不跟随未知重定向。凭据使用受控文件或标准输入，不能放在命令参数、标题和公共日志中。

网络超时仅表示结果未确认；源站 Authorization 头通常在 TLS 建立后发送，不能凭一个超时断言代理按该头阻断 TLS。需要诊断时在用户授权范围内记录无敏感内容的阶段耗时和状态，不使用含请求头的 verbose/trace 报告。

未知远端副作用先查原任务或幂等键，不重新提交。已暂停的任务不会因升级或恢复流程自动获得重测授权。桥数据库不是通用外部 API 审计账本；没有记录不等于调用从未发生，执行者的文字总结也不能替代真实工具结果。
