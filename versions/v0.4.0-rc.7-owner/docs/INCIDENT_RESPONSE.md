# 消息延迟与未回复的排查

本文是通用维护指南。部署者的聊天、外部 API 地址、实际任务标识、现场时间线及原始日志应只留在部署环境的私密记录中。

## 按阶段定位

| 阶段 | 核对 | 处理 |
| --- | --- | --- |
| 未入库 | 登录、轮询、白名单 | 先定位接收问题，不创建回复任务 |
| ready 但未领取 | 池中真实handle、忙闲、实际next及补位入口 | 恢复可运行的常驻消费者；人工救援不能记自动验收通过 |
| 已领取但未开始 | 原交接文件、真实原生任务状态 | 创建结果未知先查询，不重复派发 |
| 已开始但未提交 | 工具截止、权限等待、任务依赖、执行者状态 | 将长操作隔离到独立执行者，其他空闲池员继续领取 |
| 已提交未 accepted | 原 request 状态、delivery 阶段 | pending 继续查询；unknown 先核对，禁止另起 ID 重发 |
| accepted 但未 ack | 最终请求与执行步骤 | 无未决步骤时可恢复确认；有 started 时先核对步骤 |
| accepted 但手机未显示 | 手机核对、上游回执 | 单独记录手机送达，不能把 accepted 当成手机显示 |

记录接收、领取、执行开始、提交、accepted 和手机显示各阶段的 UTC 时刻。缺失字段写未记录，不能从可变的租约活动时刻倒推首次领取。公开问题只包含脱敏故障码与必要的汇总。

## 租约、步骤和恢复

- 每事件只有一个实际执行者，使用原始私密交接里的完整 token。不能从数据库取当前 token 充当所有权证明。
- `stale_lease` 必须结合真实退出码和 `lease_reason` 核对；文字报告不足以证明桥误拒绝。
- `started` 表示外部结果尚未结清，超时不自动完成。核对真实结果后按步骤协议结清，不能为发最终回复跳过保护。
- 最终回复提交后不再开始新的工具步骤。异步回复仍 pending 时不显式 ack。
- 刷新后确认旧任务及工具确已停止，再按原交接恢复；远端已提交的操作不能因本地进程结束就自动重做。
