# 常驻池检查

本文提供通用检查项，不包含现场数据，也不表示部署已通过验收。

| 检查项 | 合格证据 |
| --- | --- |
| 池建立 | 主代理用真实工具创建/查询多个原生常驻worker，记录slot和真实handle |
| 持续消费 | 主聊天无人操作，两批事件由原有handle直接next/reply，不逐条spawn |
| 并行回复 | 长任务期间其他池员开始并先回复，独立结果不按领取序号等待 |
| 所有权 | 各worker独占原交接，每事件完整token、正常renew、步骤和稳定request |
| 容量 | 记录实际池大小、忙闲、等待和资源；全池忙不宣称零排队 |
| 授权隔离 | 核实原生等待范围和独立观察/反馈，不能凭running猜授权状态 |
| 换班 | 先确认新slot运行，再让旧slot停新next并收尾，其余池员不断服务 |
| 刷新恢复 | 真实启动入口恢复唯一桥及原生池、核对交接，无入口记未接入 |

hook只读检测；wake、surface=main、dry_run、health或手工并行均不能证明自动补位/刷新恢复。反过来，常驻消费者直接处理消息不要求每条有新spawn或wake记录。

ready=0且leased>0可以正常工作；停滞按具体代码和活动年龄核对。没有原生授权证据记原因未知，不代批准、不扩白名单或换主机绕过。未知外部结果不重做。
