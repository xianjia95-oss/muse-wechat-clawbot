# 外部 API 失败不能挡住微信消息

> 隐私说明：服务名称、外部主机及调用标识已作示例化处理；.example地址不可作为实际请求目标。实际目标与任务标识只能从部署环境的私密原始交接取得，不得从本文示例恢复或替换。

外部任务可能因网络失败、重复尝试或原生域名授权而长时间等待。授权尚未通过不能当成 HTTP 超时；先在目标环境核实权限等待的影响范围，再隔离任务和反馈路径，不预设平台行为。

本规则适用于生图、模型列表、联网测试等外部任务。它是 Muse 执行者和调度者的契约，不是桥内置的生图客户端；桥不能拦截 Muse 绕过 helper 自行执行的 curl/工具调用。必须将本规则接入真实主代理与子任务指令，并做手机验收。

## 按运行模式隔离，保持唯一回复者

当前本地候选采用[固定对话负责人](CONVERSATION_OWNER.md)。`status.conversation.mode=coordinator`时，只有原负责人持有session和微信task-file并执行next/reply。两个[文字草稿执行者](MUSE_EXECUTORS.md)不访问外部API、不接收会话凭据、不回复微信；不能将它们改成旧的直接回复worker池。主代理负责真实角色启动与维护，不逐条等hook再派发。

外部工具采用[后台工具流程](BURST_MESSAGES.md)：负责人保存原事件、稳定checkpoint及真实工具归属，将可信脚本enqueue到Linux监督器，取得job ID后立即继续next；逐轮回收完成项、正常续租并统一回复。显式configure为总活动2、IO2、CPU1、排队32；这不是原生模型任务上限。负责人不得同步curl、sleep、反复重试或等待权限提示。没有经验证的异步入口时，说明该操作尚不能隔离执行并暂停它，继续短消息消费；不能谎报已在后台运行。

`legacy_workers`仅保留旧安装兼容：各真实消费者直接next/reply，一个等待时其他空闲者可处理。coordinator不得恢复旧池、绕过session或从数据库抄token。真实角色、工具监督器和手机回复分别验收；更改文档、登记slot或本地模拟通过不能证明云端已经并行。

## 域名授权只暂停相关任务

主代理与负责人都不直接发起可能暂停自身的受控访问。发起前验证独立、可查询的真实工具入口，保存原归属与handle；受控访问只留在该原执行者。文字草稿邮箱不提供这项能力。没有可用入口就暂停该访问并继续接收其他消息，不换域名、代理、工具或执行者绕过权限。把域名发进微信不等于通过Muse原生权限检查。

1. 只有取得真实授权证据并关联事件后，才记录`waiting_for_authorization`、event/task归属、所需域名/操作、检测UTC时间，以及平台实际提供的授权标识；未提供就如实记录。coordinator负责人可用`muse task --state waiting_for_authorization`和当前revision保存状态，它是负责人报告，不会自动探测弹窗或批准权限。旧模式保留私密台账。不要记录带密钥URL或提示全文；checkpoint仍只有started/completed，不能用授权状态冒充步骤完成。
2. 已核实阻塞时，由仍能运行的唯一负责人用原task-file/session-file发送稳定`--progress --reply-id`，例如“访问 example.com 需要在 Muse 中确认授权，此任务已暂停，未继续重试。”不能假定已暂停的执行者还能发通知，也不能把桥凭据交给它。按阶段固定ID/正文，只在状态变化时反馈；progress不final、不ack。无法读取真实原因时不套用授权文案；独立反馈路径不可用就记未发送，不声称手机收到。旧模式须明确唯一反馈职责，不能让两worker同时消费同一事件。
3. coordinator负责人在等待期间继续next、回收其他完成项并处理短消息。独立结果审核后即可回复，不按领取顺序等齐一批。文字执行者与工具名额分别有限，新增同类长任务可能排队；不能以此停止短消息消费。原事件需正常续租并有界复查真实执行状态，无法续租就停止新操作、保留现场，不清租约、不抄数据库token。没有异步入口的访问保持未执行，不能假报后台任务。
4. 授权仅在 Muse 实际提供的原生入口按用户选择处理；不把微信里的“同意”自动转成平台批准，不自动扩大白名单。原生批准后先核对任务、权限范围、有效租约、已有步骤和远端结果，再恢复尚未执行的操作；拒绝/撤销则停止该操作并如实反馈，未决外部效果先核对。不能因授权结束或租约到期就盲目重新生图。

授权等待和 HTTP 执行预算分别记录，批准后沿用原尝试记录。平台可能暂停单个任务，也可能影响主会话；必须在目标环境验证。若其他运行也会暂停，报告隔离不支持或未核实，不能保证续租、反馈或新消息继续处理。

### 不操作弹窗与点击拒绝分别处理

未选择授权与明确拒绝是不同状态。不能把弹窗未操作或查询只返回 running 当成拒绝，也不能代用户作出选择。

| 已核实事实 | 微信应反馈 | 执行与收件状态 |
| --- | --- | --- |
| 真实授权提示待选择，且已关联本任务 | 访问具体域名需要在Muse确认，该任务正等待授权 | 保留原执行者与事件，停止新增尝试；固定负责人继续领取独立消息；旧模式由其他空闲worker消费 |
| 原生结果明确拒绝/撤销 | 本次访问被拒绝，未取得所需结果 | 停止该操作；核实既有步骤和远端效果后如实最终回复，accepted后确认事件；有未决效果则仅progress并继续核对 |
| 独立观察到约定反馈时限已到，但拿不到授权状态 | 获取模型列表在约定时限内未返回，暂无法确认具体阻塞原因 | 仅反馈已核实的任务等待超时，不称为HTTP超时、拒绝或任务已取消，不重试、不自动结清步骤或ack |

等待任务本身不能充当唯一反馈者。独立观察/反馈侧须有经验证的运行路径、原交接及明确职责；创建文字执行者或工具监督器不会自动接通原生权限回调。同一授权动作返回后才补发通知，不算等待期间反馈通过。新消息持续消费、原生授权状态可观察、等待期间微信反馈分别验收。

本仓库没有接收 Muse 原生授权事件、读取权限弹窗、批准或取消原生请求的接口。部署时核实平台真实可读状态；只能看到 running 时记原因未知，可按事先约定的反馈截止说明超时，但不宣称已取消请求或已获知授权原因。

## 次数和总耗时都要有上限

以下为新任务的建议初始预算，写入本任务私密记录后执行；不是已在云端生效的配置，也不保证上游必能在预算内完成。

| 操作 | 初始边界 | 到达边界后 |
| --- | --- | --- |
| 建立连接 | 每次连接超时5秒 | 记录实际失败阶段，不无限等待 |
| 无副作用的连通性/模型列表查询 | 每次最多20秒；瞬态故障最多额外重试1次；含退避总共不超过45秒 | 返回已核实失败，不继续换域名、换工具、换班重试 |
| 发起生图等可能计费/创建远端任务的请求 | 默认只提交1次；本地执行预算初始120秒，包含请求、等待与已有任务的状态查询 | 超时不重新提交。先查原远端任务或幂等键；结果未知则记录待核对 |

认证/权限失败、目标路径或参数错误不做自动重试。只读请求的瞬态故障重试仍须满足剩余总预算；429按服务端退避提示处理，等待将超预算则结束本轮。不得把一个外部错误反复当成新任务：相同事件/步骤的尝试次数、开始时间、截止时间和原远端任务ID应持久化，换班、换工具或新建job不得重置预算。只读查询重试和有副作用的重新提交是不同操作，不能互相套用策略。

确实需要更久的生成任务，可在执行前根据服务接口和用户要求设定有界预算并记录原因；不能在连续失败时自动一次次延长。异步生成优先保存远端任务ID后有限轮询，不能反复新建生成任务。截止后不再发起新操作；后续核对作为有记录的独立跟进，不占住全局调度循环。

通过 tool-job 执行时，监督器的 --timeout 设置为整段脚本预算（只读诊断45s、生图初始120s），而非每次请求预算；脚本内部也要限制次数与截止。已有监督器会终止超时的本地进程组且不会自动重跑，但这不能撤销远端已发生的动作，也不能阻止模型在监督器外再次调用 API。

## 失败反馈与结果核对

微信只发真实答案、实际产物或已核实阻塞，不发占位确认；真实媒体另按MEDIA.md发送。确认连接失败、鉴权失败或已到截止时，给出对应实际结果，不先花十分钟继续试验。已确认失败且步骤可安全结清时记录真实失败并最终回复；远端效果未知或started尚待核对时，先用稳定progress说明已核实的超时和“结果未确认、已停止重试”，保留原交接与步骤，不自动completed或提前ack。固定负责人继续处理其他消息，不等原任务核对全部结束才next。

未收到生成响应不能直接说“没有生成”或“不会扣费”。已有远端ID、幂等键和产物要先核对；不换ID重做。API凭据不放命令参数、公共日志或任务标题，不为排查切换未授权主机。外部API当前的暂停重测边界见 [运行环境恢复](RUNTIME_RECOVERY.md)，本规则不授权重新连接或生图。

## 用无副作用任务验证

在隔离任务中使用本地模拟端点返回超时/临时失败，记录尝试次数及总耗时；不调用真实生图API。长任务进行时，从微信连发编号短消息，主聊天不人工介入，核对短任务在长任务结束前已经开始并回复。再核对失败任务到预算后停止、产生对应结果/待核对反馈，同一任务没有因换班或换工具继续新建尝试。保存真实任务handle、event/request关联与UTC时刻；人工救援和本地mock都不能代替自动消费验收。

授权隔离验收使用已经存在的原生待授权状态，不再请求目标域名制造提示，也不调用真实生图。先用无副作用本地短任务核对其他任务仍可运行；再仅从微信发送独立编号消息，要求coordinator负责人持续自动领取并在原授权尚未处理时回复，不另起旧回复worker救援。保存等待状态、短任务 handle、领取/开始/accepted/手机时刻及人工介入情况。无待授权样本就记未执行；人工打开主聊天才能派发则自动链路失败。完整执行步骤见[授权阻塞修复指令](给Muse修复域名授权阻塞的指令.txt)。

另外分别验收：保持现有弹窗不操作时，原任务已有微信阻塞反馈；用户自行选择拒绝后，原任务如实反馈并安全收尾。拒绝项由用户选择，不代点。平台状态不可读时，应验证独立反馈截止能产生原因未确认的真实超时说明，不能把该项当成精确授权通知通过。此处为本地待验证修订，不表示云端已接入或用户已经同意发布。
